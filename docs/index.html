What goes wrong without rails

AI coding agents have three reliable failure modes. Topia attacks each one directly.

Skipped steps

"add user auth"
↓
write code ↔ ???
       ↔ no plan, no tests

Agents jump straight to code. No requirements, no plan, no failing test first. Bug count drifts up; reviewers burn out.

Forgotten context

Session 1: pick approach A
Session 2: redo discovery
Session 3: pick approach B

Every new session starts cold. Decisions, gotchas, "we tried that already" — gone. The agent re-asks what it should already know.

Bad work shipped

code → secret in commit
     → SQL injection
     → unverified claim

Secrets leak into git. OWASP patterns slip past review. Agents claim "tests pass" without running them. No gate, no proof.

Topia doesn't make agents smarter — they already know how to code.
Topia gives them rails the model can't skip.

How it works

A request hits Topia. Eight things happen in order. The agent can't skip any of them.

1
Route

skill-router maps the request to a workflow. "add auth" routes to build; "production is down" routes to incident; "research X" routes to research. No more ambiguous prompts.

2
Recall

Before any work starts, the agent pulls prior context: past decisions from journal, codebase shape from scout, and (if registered) prior learnings from the agora-code MCP — persistent memory across sessions.

3
Plan

idea elicits the WHAT (5 probing questions, max), then plan writes a phase-by-phase blueprint. Optionally, adversary red-teams the plan before code is written — finds edge cases at plan-time, not at review-time.

4
Test (first)

test writes failing tests against the acceptance criteria from the plan. Red phase. No implementation yet. TDD enforced, not suggested.

5
Implement

fix writes code until tests go green. If an error surfaces, debug finds the root cause before another patch attempt. No guessing.

6
Gate

Three checks run before commit: preflight (logic, completeness, regressions), sentinel (secrets, OWASP, dep audit), review (quality, conventions). Each is a gate, not a suggestion — BLOCK verdicts stop the commit.

7
Verify

verification runs lint + type-check + tests + build. hallucination-guard confirms every import and API call actually exists. completion-gate validates the agent's claims against the evidence trail — "tests pass" requires the output.

8
Persist + commit

journal writes the decision (and pushes it to agora-code if registered). git creates a semantic commit. Next session's recall step now sees this decision.

Eight steps, one prompt. The model fills in the work; the toolkit enforces the order.

Persistent memory across sessions

The #1 complaint about AI coding agents is amnesia. v1.1.0 ships with agora-code vendored as an optional MCP backend — SQLite-backed memory, symbol index, semantic recall.

Without memory

Mon: agent reads 12 files,
     decides on Zustand
Wed: agent re-reads 12 files
     picks Redux instead
Fri: re-asks "where's auth?"

Every session starts cold. Discovery cost paid 3× per week. No durable answer to "why did we decide this?"

With agora-code

Mon: decision stored
Wed: recall_learnings("state")
     → "we picked Zustand on
        Mon because [reason]"
Fri: get_file_symbols("auth")
     → lines, no re-read

Decisions, gotchas, file symbols persist. recall_learnings surfaces them at the start of the next related task — before the agent re-discovers.

What dev teams actually see

Forget token counts. These are the behaviors that change when an agent runs on Topia.

🔒

Secrets stay out of git

sentinel runs as a pre-commit hook. Hardcoded API keys, AWS credentials, and OAuth tokens are blocked — not flagged in a comment, blocked. Same for OWASP top-10 patterns.

✅

Tests precede code

build Phase 3 writes failing tests against the plan's acceptance criteria before Phase 4 implements anything. PRs ship with tests that map 1:1 to requirements. Reviewers stop having to ask "but where are the tests?"

📝

"Why did we do it this way?"
has an answer

Every architecturally meaningful decision goes through journal's 3-criteria gate (sum ≥ 11, each axis ≥ 3, counter-test filled). The ADR persists to .topia/adr/ and (optionally) to agora-code's recall index.

🔎

"Tests pass" requires the output

completion-gate is a lie detector. Every claim ("tests pass", "build is green", "deployed") must have evidence in the tool-call trail. Default-FAIL mindset — no evidence, no PASS.

🌐

Same rules across IDEs

One source of truth in skills/ compiles to Claude Code, Cursor, Antigravity, Codex, OpenCode, and OpenClaw. Switch IDEs without rewriting your workflow rules.

⚙

Imports actually exist

hallucination-guard fires after any AI-generated code introduces new imports or API calls. Phantom functions, typosquatted packages, and made-up SDK methods get caught before commit, not in production.

Workflows

Three top-level commands cover most of what you'll run.

/topia build

Default for any code change — features, fixes, refactors.

0 RESUME — detect existing plans
1 UNDERSTAND — scout + idea + recall
2 PLAN — phase files + adversary review
3 TEST — failing tests first
4 IMPLEMENT — fix until green
5 GATE — preflight + sentinel + review
6 VERIFY — verification + hallucination-guard
7 COMMIT — semantic git commit

/topia rescue

Modernize legacy code without breaking it.

0 RECON — autopsy health score
1 SAFETY NET — characterization tests
2 SURGERY — one module per session
3 CLEANUP — remove legacy markers
4 VERIFY — before vs after score

/topia team

Parallel work when 5+ files or 3+ modules.

1 DECOMPOSE — dependency DAG
2 ASSIGN — worktree per stream
3 EXECUTE — parallel agents
4 MERGE — conflict resolution
5 VALIDATE — completion-gate

What this looks like in practice

Concrete situations a developer or small team runs into, and the path Topia takes through them.

"I just inherited this codebase."

  1. /topia onboard — scans repo, drafts CLAUDE.md + .topia/
  2. /topia autopsy — per-module health scores, hotspot map
  3. /topia retro — commit history patterns, who-shipped-what

In 5 minutes you have a map, a health report, and a shipping log — before reading a single line of source.

"I need to add a feature without breaking the rest."

  1. /topia build "add user auth with magic-link"
  2. Routes through idea → plan → test (red) → fix (green) → gates → commit
  3. journal stores the design decision for future "why did we do it this way?"

One prompt produces a planned, tested, security-scanned commit. Reviewers see tests-first PRs.

"Production is down."

  1. /topia incident — triage to P1/P2/P3, contain BEFORE investigating
  2. /topia debug — find root cause (no guessing at fixes yet)
  3. /topia fix + /topia deploy — ship the patch; watchdog verifies live
  4. /topia journal — postmortem as ADR

Containment first; root cause before patch; postmortem captured for the next on-call rotation.

"This module is a mess and tests barely exist."

  1. /topia rescue — multi-session legacy refactor orchestrator
  2. autopsy → safeguard (characterization tests + rollback tags) → surgeon (one module per session)
  3. Before/after health score on completion

Refactor with safety nets. Tests capture current behavior before a single line gets edited.

"I want to steal a pattern from a GitHub repo."

  1. /topia graft <url> --port (or --copy, --improve, --compare)
  2. 5-dimension challenge gate: license, stack fit, scope, quality, maintenance
  3. Adaptation plan → written with your stack's conventions

Adopt before you copy. Apache 2.0 dropped into MIT? You get the attribution prompt before any file lands.

"My team needs to ship 5 changes this sprint without conflicts."

  1. /topia team "<tasks>" — decomposes into dependency DAG
  2. Each independent stream gets its own git worktree + parallel agent
  3. completion-gate validates every claim before merge

Parallel work without merge-conflict roulette. Each agent sees a clean working tree.

"I'm starting a new project from a one-paragraph description."

  1. /topia scaffold "<description>"
  2. Pipeline: idea → plan → design → fix → test → docs → git
  3. Output: working project, passing tests, first commit, documented decisions

0 to production-ready in one orchestrated pass. No "I forgot to add tests" three sprints in.

"Why did we pick X back in March?"

  1. If agora-code MCP registered: recall_learnings("X") from neural-memory
  2. Else: journal reads .topia/adr/ ADRs
  3. Either way: the decision, the rejected alternatives, the rationale

Decisions persist as first-class artifacts. The "why" survives team turnover.

Persistent memory (optional)

agora-code MCP

Easiest path: /topia finalize inside Claude offers to install this for you.

# Manual install — needs Python 3.10+
pip install ./mcp-servers/agora-code

# Register in the project
cat >> .mcp.json << 'EOF'
{ "mcpServers": { "agora-memory": {
  "command": "agora-code",
  "args": ["memory-server"] } } }
EOF

Skills detect this MCP automatically and route recall/learning through it. Skip it and Topia uses file-based persistence.

Do not run agora-code install-hooks --claude-code. Topia's hooks are canonical — running both installers produces a fragile dual-owner hook chain. Why →
